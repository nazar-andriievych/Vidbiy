# Відбій — вимоги (MVP)

## Мета

Будильник, який не дзвонить, поки у вибраному регіоні триває повітряна тривога,
і дзвонить одразу після відбою. Якщо даних про тривогу немає — дзвонить як звичайний будильник.

Некомерційний проєкт: усе має залишатися безкоштовним, без реєстрації, телеметрії та збору даних.

## Функціональні вимоги

- **FR-1.** Користувач створює кілька будильників: час і дні тижня.
- **FR-2.** Для кожного будильника є перемикач «враховувати тривоги». Вимкнено — це звичайний будильник.
- **FR-3.** Користувач обирає регіон: область, район або громаду.
- **FR-4.** У момент дзвінка застосунок перевіряє стан тривоги в регіоні:
  - тривоги немає — дзвонить одразу;
  - тривога є — не дзвонить і чекає відбою.
- **FR-5.** Після відбою будильник дзвонить **одразу**.
- **FR-6.** Відбій, що стався до часу будильника, ні на що не впливає: будильник дзвонить у свій час.
- **FR-7.** Крайній час: якщо до нього відбою немає, будильник дзвонить однаково.
  Задається як час того ж дня, пізніший за будильник. За замовчуванням — час будильника + 2 год.
- **FR-8.** Поки будильник чекає відбою, показується тиха нотифікація
  «Будильник відкладено через тривогу» з поточним статусом і часом останнього оновлення.
- **FR-9.** Відкладення (snooze) на 5 хв.
- **FR-10.** Мелодія — системний вибір рингтона; перемикач вібрації.

### Регіон

Тривога рахується, якщо вона діє **на території, що покриває обраний регіон**:

| Обрано | Будильник чекає, якщо тривога оголошена в... |
|---|---|
| Громада | цій громаді, її районі або її області |
| Район | цьому районі або його області |
| Область | цій області |

Тривоги в сусідніх громадах чи районах тієї ж області **не** враховуються.

## Нефункціональні вимоги

- **NFR-1 Fail-safe.** Немає інтернету, сервер недоступний або дані старші за **3 хв** —
  будильник дзвонить. Це стосується і моменту дзвінка, і періоду очікування відбою.
- **NFR-2 Надійність.** Будильник спрацьовує в режимі енергозбереження, після перезавантаження
  і в режимі «Не турбувати». Основний тестовий пристрій — Samsung.
- **NFR-3 Затримка.** Від офіційного відбою до дзвінка — не більше 2 хв.
- **NFR-4 Приватність.** Без реєстрації, геолокації, аналітики. Сервер не знає регіону користувача.
- **NFR-5 Платформа.** Android 8+ (minSdk 26).
- **NFR-6 Мова.** Українська.

## Архітектура

```
Телефон ──(у момент дзвінка та кожні ~30 с під час очікування)──► Проксі (Cloudflare Workers)
                                                                     │ кеш ~15 с, токен тут
                                                                     ▼
                                                                  alerts.in.ua API
```

- **Джерело даних:** alerts.in.ua API. Токен зберігається лише на сервері (вимога їхніх правил).
- **Сервер:** Cloudflare Workers, безкоштовний план без картки. Віддає повний список активних тривог;
  телефон сам фільтрує свій регіон.
- **Застосунок:** Kotlin + Jetpack Compose. Очікування відбою — foreground service.
- **Структура репозиторію:** Android-проєкт у корені, сервер у `server/`.

## Не в MVP (пізніше)

- Налаштування правил під користувача: затримка N хв після відбою, поріг застарілих даних,
  «відбій незадовго до будильника → зсунути дзвінок», повторна тривога під час очікування.
- Push через Firebase Cloud Messaging замість опитування.
- iOS (окремий проєкт: AlarmKit + push, потрібен платний акаунт Apple).
- Поступове наростання гучності, власні мелодії, віджети, англійська мова.
