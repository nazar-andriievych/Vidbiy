# Проксі «Відбій»

Воркер на Cloudflare Workers між застосунком і alerts.in.ua.
Тримає токен подалі від телефона й кешує відповіді, щоб не перевищити ліміти alerts.in.ua.

Контракт ендпоїнта — у [`../docs/proxy-api.md`](../docs/proxy-api.md).

## Локальна розробка

Локально працюємо на підробці апстріму — справжній токен на робочу машину не кладемо.

```bash
npm install
cp .dev.vars.example .dev.vars
npm run dev
```

```bash
curl.exe http://127.0.0.1:8787/health
curl.exe http://127.0.0.1:8787/v1/alerts
```

> У PowerShell `curl` — це аліас до `Invoke-WebRequest`. Пиши `curl.exe`
> або `irm <url> | ConvertTo-Json`.

### Керування тривогою вручну

Основний спосіб перевіряти застосунок, не чекаючи на справжню тривогу:

```bash
curl.exe "http://127.0.0.1:8787/mock?scenario=alert"   # оголосити тривогу
curl.exe "http://127.0.0.1:8787/mock?scenario=clear"   # оголосити відбій
curl.exe "http://127.0.0.1:8787/mock?scenario=down"    # апстрім віддає 429
```

Щоб телефон дістався до локального воркера, запускай `npm run dev -- --ip 0.0.0.0`
і став у застосунку адресу `http://<IP-комп'ютера>:8787`.

## Розгортання

Одноразово:

```bash
npx wrangler login                            # відкриє браузер
npx wrangler secret put ALERTS_IN_UA_TOKEN    # спитає токен і відправить прямо в Cloudflare
```

Далі:

```bash
npm run deploy
```

Адреса: `https://vidbiy-proxy.nazar-dev.workers.dev`

Справжні дані перевіряємо вже на розгорнутому воркері — там токен є, і він недосяжний.

## Секрети

Токен alerts.in.ua **ніколи не потрапляє ні в git, ні в застосунок, ні на робочу машину**.
Він існує у двох місцях: у менеджері паролів і в секретах Cloudflare.

Секрети Cloudflare односторонні: `wrangler secret put` записує, прочитати назад не може ніхто.

## Чому саме так

- **Кеш у Durable Object, а не в пам'яті воркера.** Ізолятів Cloudflare піднімає багато,
  кеш у кожного свій, і разом вони пробивають ліміт alerts.in.ua — це відтворилося на проді.
  Durable Object існує в одному екземплярі на весь світ, тож обмежувач частоти один на всіх.
  Cache API не підходить: на безкоштовному `*.workers.dev` він не працює.
- **Помилка апстріму віддається як `200`** із чесним `age_seconds`. Застосунку потрібні дані
  для рішення «дзвонити чи ні», а не помилка транспорту.
- **`alerts: []` і `alerts: null` — різні стани.** Перевірено-чисто й ми-не-знаємо.
  Будильник дзвонить в обох випадках, але причини різні.
- **Провайдер відокремлений.** `alerts-in-ua.ts` — єдиний файл, що знає про alerts.in.ua;
  `cache.ts` приймає будь-яку функцію `() => Promise<UpstreamResult>`. Другий провайдер
  додається поруч, без переробки.
