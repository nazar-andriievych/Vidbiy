# Як перевіряти «Відбій»

Три рівні, від швидкого до повільного:

1. **Юніт-тести** — уся логіка рішення: секунди, на кожну зміну.
2. **Сценарії на телефоні** проти mock-воркера — те, чого юніт-тести не бачать: Android,
   AlarmManager, служби, дозволи, Samsung. Хвилини на сценарій.
3. **Живий прогін** із журналом — реальні тривоги, кілька ночей.

Правило: що можна перевірити юніт-тестом, перевіряємо юніт-тестом. На телефоні лишається
лише те, що залежить від Android. Як розбирати незрозумілий дзвінок — `docs/debugging.md`.

## 1. Юніт-тести

```
.\gradlew.bat test                       # застосунок (JUnit, без телефона)
cd server; npm test                      # сервер (vitest)
cd server; npm run typecheck
.\gradlew.bat connectedDebugAndroidTest  # UI-тести: потрібен телефон або емулятор
```

## 3. Сценарії на телефоні (mock-воркер)

Живу тривогу на замовлення не отримаєш, тож поведінку перевіряємо проти локального воркера:

```
cd server; npm run dev -- --ip 0.0.0.0          # MOCK=1 у server/.dev.vars
# debug-збірка з PROXY_URL на адресу ПК (див. app/build.gradle.kts), Windows Firewall — порт 8787
curl.exe "http://127.0.0.1:8787/mock?scenario=alert&uid=75"              # червона в районі
curl.exe "http://127.0.0.1:8787/mock?scenario=alert&uid=75&level=yellow" # жовта
curl.exe "http://127.0.0.1:8787/mock?scenario=alert&uid=75&started_hours_ago=25"
curl.exe "http://127.0.0.1:8787/mock?scenario=clear"
curl.exe "http://127.0.0.1:8787/mock?scenario=down"
```

**Умови за замовчуванням** (якщо в рядку не сказано інше): будильник на найближчу хвилину,
регіон — громада 702 (Буча: покривають 702, 75, 14), «Будь-яка», пауза 0, без крайнього часу.
Після кожного сценарію звірити журнал рішень (`docs/debugging.md`). Mock тримає **одну** тривогу
за раз: поєднання рівнів у різних регіонах (FR-27) перевіряють юніт-тести.

Для дзвінка й відкладення зручно ставити дзвінок і відкладення по 1 хв:
`.\gradlew.bat installDebug -Pvidbiy.ringMinutes=1`. Після сесії повернути звичайну збірку.

### Як проходити

- **Пріоритет.** **1** — збій означає будильник, що не задзвонив, або задзвонив під час тривоги
  без причини. **2** — текст, вигляд, зручність.
- **Швидкий набір** — після кожного встановлення на свій телефон (~30 хв):
  А1, А2, А9, Б1, Б5, В2, Г2, Г9, Ж5, Ж6, Ж11.
- **Повний прогін** — перед тим як залишити збірку на щодень: усі сценарії пріоритету 1, решта —
  у міру змін у відповідних місцях.
- **Готово**, коли: `gradlew test` і `npm test` зелені; усі сценарії пріоритету 1 ✅ на Samsung на
  цьому коміті; кожен ❌ записаний з тим, що побачили.
- **Пристрої.** Основний — Samsung (усі сценарії). Емулятор Android 8.0 (API 26, minSdk) — А1, Г2,
  Г9, Ж5: найстаріша підтримувана версія. Емулятор Android 14+ — З4: дозволи, яких на старіших немає.
- **Протокол.** Скопіювати `docs/test-runs/TEMPLATE.md` у `docs/test-runs/<дата>.md`, записати
  коміт (`git rev-parse --short HEAD`), модель телефону, версію Android і One UI; результат кожного
  сценарію — ✅ / ❌ (+ що побачили) / — (не перевіряли). Таблиці нижче — специфікація, результатів
  у них не пишемо.

| Е6 | 1 | Видалити будильник, що чекає | Очікування й сповіщення зникли |
| Е7 | 1 | Під час очікування змінити регіон місця, яким він користується | Поточне очікування не змінилось (журнал: старі UID); наступного разу — новий регіон |
| Е8 | 2 | Додати перше місце; ввести назву довшу за 24 символи | Перше стає основним; назва не довша за 24 символи |
| Е9 | 2 | Змінити регіон місця з будильниками | Попередження з переліком будильників; після — вони в новому регіоні |
| Е10 | 2 | Видалити не основне місце з будильниками | Попередження; будильники лишили регіон, без назви місця |
| Е11 | 2 | Спробувати видалити основне місце | Не дає, доки основним не зроблено інше |
| Е12 | 2 | Зробити основним інше місце | Новий будильник і разовий режим беруть його |

### Ж. Надійність (NFR-2, NFR-2a, LOGIC-1)

| # | Пр. | Сценарій | Очікуємо |
|---|---|---|---|
| Ж1 | 1 | Екран вимкнено **30+ хв** під час очікування, телефон не на зарядці | `poll` кожні ~30 с без пропусків (`gapSeconds`); Б1 після цього спрацьовує вчасно |
| Ж2 | 1 | Під час очікування `adb shell dumpsys deviceidle force-idle`, через 5 хв `clear` | Дзвонить за ≤2 хв. Після: `adb shell dumpsys deviceidle unforce`, `adb shell dumpsys battery reset` |
| Ж3 | 2 | `adb shell dumpsys battery unplug`, `adb shell am set-standby-bucket ua.vidbiy.app.debug rare`, будильник через 5 хв | Дзвонить вчасно. Після: `set-standby-bucket … active`, `dumpsys battery reset` |
| Ж4 | 1 | Samsung: застосунок у «Застосунки в глибокому сні» (Батарея → Обмеження фонового використання) | Записати: чи дзвонить будильник, чи йдуть `poll`, чи є банер на головному |
| Ж5 | 1 | Будильник через 5 хв, перезавантаження, **одразу розблокувати** | Дзвонить вчасно, звичайна перевірка тривоги |
| Ж6 | 1 | Будильник через 5 хв, перезавантаження, **не розблоковувати** | Дзвонить вчасно поверх блокування: «Телефон перезавантажився», типовий звук будильника. «Відкласти» працює й до розблокування. Після розблокування: разовий будильник вимкнений, відкладення видно в картці, журнал — `locked_ring` |
| Ж7 | 1 | Перезавантаження під час очікування, одразу розблокувати | Очікування відновилось (журнал `restore_wait`) або задзвонив |
| Ж8 | 1 | Перезавантаження під час очікування, **не розблоковувати** | Одразу після завантаження дзвонить «Телефон перезавантажився»; після розблокування очікування не відновлюється |
| Ж9 | 2 | Samsung: автоперезапуск (Обслуговування пристрою → Автоматизація) на найближчі хвилини, будильник через 5 хв після нього | Записати: чи телефон після автоперезапуску заблокований; будильник дзвонить (як Ж5 або Ж6) |
| Ж10 | 1 | `installDebug` під час очікування | `restore_wait` з `MY_PACKAGE_REPLACED`, далі `poll` без пропусків; після відбою — дзвінок |
| Ж11 | 1 | Під час очікування `adb shell am crash ua.vidbiy.app.debug` | Не пізніше ніж за 5 хв дзвонить «Збій у застосунку» (вартовий), а не мовчить до крайнього часу |
| Ж12 | 1 | Під час очікування `adb shell am broadcast -n ua.vidbiy.app.debug/ua.vidbiy.app.alarm.DebugFailureReceiver` (лише debug) | За ≤30 с дзвонить «Збій у застосунку»; журнал — `LOOP_FAILURE` |
| Ж13 | 2 | Телефон вимкнено на час будильника з датою, увімкнено після | Будильник вимкнувся без дзвінка (FR-1a) |
| Ж14 | 2 | Змінити час або часовий пояс вручну в налаштуваннях | Наступний дзвінок у картці перерахувався правильно |
| Ж15 | 2 | Резервна копія: `installDebug -Pvidbiy.backup=true`, `adb shell bmgr backupnow ua.vidbiy.app.debug`, видалити, встановити знову | Будильники й місця повернулись і стоять у розкладі (NFR-4) |

**Не використовувати** `adb shell am force-stop` замість `am crash`: force-stop за задумом Android
скасовує всі будильники застосунку, і після нього не задзвонить жоден застосунок.

### Що перевіряють лише юніт-тести

Поєднання рівнів у кількох регіонах одночасно (FR-27), переходи на літній і зимовий час,
пошкоджений JSON у сховищі (LOGIC-2), рішення «автовідкласти чи здатися», формат відповіді
проксі (контракт), доба очікування як остання страховка.

## 4. Живий прогін

2–3 ночі з реальним будильником проти бойового сервера, з журналом. Щоранку:

1. `adb exec-out run-as ua.vidbiy.app.debug cat files/decisions.jsonl > tmp/decisions-<дата>.jsonl`
2. `node tools/check-region.mjs 702`
3. Порівняти рядки `ring` з офіційним застосунком «Повітряна тривога» і з виводом `check-region`.
4. **Затримка (NFR-3, ≤2 хв):** для кожного дзвінка після відбою порівняти час відбою в `/log`
   сервера (вебхук або знімок, `→ none`) плюс пауза N з часом `ring` у журналі телефона.
5. Пропуски опитування вночі: `gapSeconds` значно більше 30 означає, що Samsung присипляв службу.
