# Проксі «Відбій» — контракт API

Проксі стоїть між застосунком і alerts.in.ua. Його дві задачі:
тримати токен подалі від телефона (NFR-4) і не дати нам перевищити ліміти alerts.in.ua,
скільки б користувачів не було.

Базова адреса: `https://vidbiy-proxy.nazar-dev.workers.dev`

## `GET /v1/alerts`

Повертає всі активні **повітряні** тривоги в Україні. Регіон користувача сервер не знає
й не бачить — фільтрацію «громада → район → область» робить телефон.

```json
{
  "v": 1,
  "upstream_ok": true,
  "fetched_at": "2026-09-23T10:15:02.000Z",
  "age_seconds": 7,
  "alerts": [
    { "uid": "16", "type": "oblast", "started_at": "2026-09-23T09:40:11.000Z" }
  ]
}
```

| Поле | Значення |
|---|---|
| `v` | Версія формату. Зараз `1` |
| `upstream_ok` | Чи вдалася **остання** спроба звернутися до alerts.in.ua |
| `upstream_status` | Є лише при `upstream_ok: false`. HTTP-код апстріму або `null`, якщо запит не дійшов |
| `fetched_at` | Коли проксі востаннє **успішно** отримав дані. `null`, якщо успішних спроб не було |
| `age_seconds` | Вік цих даних у секундах на момент відповіді. `null`, якщо даних немає |
| `alerts` | Список активних тривог, `[]` або `null` — див. нижче |
| `alerts[].uid` | UID регіону з довідника alerts.in.ua, рядком |
| `alerts[].type` | `oblast`, `raion`, `city`, `hromada` або `unknown` |
| `alerts[].started_at` | Початок тривоги, ISO-8601. Може бути `null` |

Відповідь завжди `200`, навіть коли апстрім лежить. Стан описують поля, а не HTTP-код:
застосунку потрібні дані для рішення, а не помилка транспорту.

### `[]` і `null` — це різні стани

- `"alerts": []` — **перевірено, тривог немає.** Будильник дзвонить, бо все чисто.
- `"alerts": null` — **ми не знаємо.** Успішної відповіді від alerts.in.ua не було жодного разу
  (щойно піднятий воркер, відкликаний токен). Будильник дзвонить за fail-safe (NFR-1).

Результат однаковий — дзвонимо, — але причини різні, і в нотифікації вони мають звучати по-різному.
Плутати ці два стани не можна.

### Про `age_seconds`, а не тільки `fetched_at`

Поріг застарілості — 3 хвилини (NFR-1). Рахувати його як «зараз мінус `fetched_at`» не можна:
годинник телефона може бути зсунутий на хвилини, і будильник тоді або дзвонитиме дарма,
або мовчатиме під час тривоги.

Тому вік даних рахує сервер, а телефон додає до нього власний час очікування, виміряний
монотонним лічильником (`SystemClock.elapsedRealtime()`):

```
вік = age_seconds + (скільки минуло на телефоні від моменту відповіді)
```

Так розбіжність годинників не впливає ні на що.

Відповідь віддається з `Cache-Control: no-store` — інакше проміжний кеш міг би повернути
стару відповідь зі старим `age_seconds`, і вік даних став би брехнею.

## `GET /health`

```json
{ "ok": true, "mock": false, "configured": true }
```

`configured: false` означає, що на воркері не заданий `ALERTS_IN_UA_TOKEN` — тоді `/v1/alerts`
завжди віддає `alerts: null`.

## `GET|POST /mock` — лише в mock-режимі

Доступний, тільки якщо воркер запущений із `MOCK=1` (локальна розробка). У продакшні
маршруту не існує. Дозволяє керувати «тривогою» вручну й перевіряти телефон без очікування
справжніх подій:

```
curl "http://localhost:8787/mock?scenario=alert&uid=16"   # оголосити тривогу
curl "http://localhost:8787/mock?scenario=clear"          # оголосити відбій
curl "http://localhost:8787/mock?scenario=down"           # апстрім віддає 429
```

Зміна сценарію скидає кеш, тож наступний `/v1/alerts` одразу покаже новий стан.

## Кешування й ліміти

- До alerts.in.ua проксі звертається **не частіше ніж раз на 15 с** — 4 запити/хв
  при м'якому ліміті 8–10.
- Після `429` — пауза 60 с.
- Одночасні запити не множать звернення до апстріму: паралельні виклики чекають
  на один спільний запит.
- Кількість звернень до alerts.in.ua **не залежить від кількості користувачів**.

Усі запити проходять через один Durable Object — іменований об'єкт, якого в усьому світі
існує рівно один екземпляр. Саме він і дає останню гарантію.

Перша версія тримала кеш просто в пам'яті воркера, і цього виявилося недостатньо:
Cloudflare піднімає стільки ізолятів, скільки вважає за потрібне, кеш у кожного свій,
і разом вони пробивали жорсткий ліміт у 12 запитів/хв — на проді це відтворилося
десятком запитів за хвилину. Cache API замість цього теж не підходить: на безкоштовному
`*.workers.dev` він не працює, для нього потрібен власний домен.

Якщо Durable Object виявиться недосяжним, проксі віддає `alerts: null` — застосунок
задзвонить за fail-safe, а не замовкне через нашу поломку.
