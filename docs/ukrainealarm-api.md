# ukrainealarm API — конспект

Офіційний API застосунку «Повітряна тривога» (ТзОВ «Стфалкон»). Джерела:
оферта й опис API (OpenAPI) — на https://api.ukrainealarm.com/ (у репозиторії їх не тримаємо: це документи
«Стфалкон»), https://api.ukrainealarm.com/webhook-signature-validation.html,
https://api.ukrainealarm.com/webhook-message-model.html (звірено 2026-09-24).

Сторінки документації закриває бот-захист Cloudflare: `curl` отримує 403, браузер проходить.

## Автентифікація

Заголовок `Authorization: <ключ>` — **без** `Bearer`. Ключ живе лише в секретах Cloudflare
(`UKRAINEALARM_TOKEN`), ніколи в застосунку й ніколи в git.

## Ендпоїнти, які нас цікавлять

| Шлях | Що повертає |
|---|---|
| `GET /api/v3/alerts` | Регіони, де зараз щось триває, з `activeAlerts[]` за типами. Початковий знімок |
| `GET /api/v3/alerts/status` | `{"lastActionIndex": ...}` — номер останньої зміни. Дешева перевірка «чи щось змінилось» |
| `GET /api/v3/regions` | Дерево: область → район → громада |
| `POST/PATCH/DELETE /api/v3/webhook` | Підписка на вебхук: `{"webHookUrl": "..."}` |

`lastActionIndex` схожий на .NET `DateTime.Ticks` часу останньої зміни. Це не задокументовано,
тож не покладаємося.

## Регіони

Довідник застосунку (`app/src/main/assets/regions.json`) будується з `GET /api/v3/regions`
(`tools/build-regions.mjs`), тож ID ті самі. Відмінності:

| Що | Застосунок | ukrainealarm |
|---|---|---|
| АР Крим | `29` | `9999` |
| Тестовий регіон | — | `0`, ігноруємо |
| м. Харків `1293`, м. Запоріжжя `564` | громади у своїх районах | окремі регіони верхнього рівня |
| 12 перейменованих громад і районів (Самар, Шептицький, Берестин…) | чинні назви | назви до перейменування |

Окупованих районів Луганщини й Севастополя в ukrainealarm немає — тривог на них не оголошують,
тож і в довіднику їх немає (будильники, збережені з ними раніше, працюють як були).

Для Харкова й Запоріжжя застосунок рахує лише «місто → область», без району (FR-29,
`SEPARATE_CITIES` у `Region.kt`). Журнал сервера за 2026-10-04 … 10-06 показав, що тривога району
в ukrainealarm означає «район без міста»: Харківський район був у тривозі без міста ~8 год із 48,
Запорізький — ~2 год. З районом будильник мовчав би весь цей час, поки офіційний застосунок
показує місту відбій.

Типи тривог: `AIR`, `ARTILLERY`, `URBAN_FIGHTS`, `CHEMICAL`, `NUCLEAR`, `INFO`, `CUSTOM`.
**Нас цікавить лише `AIR`.** У списку постійно висить Луганська область із 2022 року —
для нас це правильно.

## Вебхук

Заголовки: `X-Webhook-Signature` (Base64), `X-Webhook-Timestamp` (Unix, секунди),
`X-Webhook-Key-Id`, `X-Webhook-Signature-Alg` (`rsa-sha256`).

Підпис — RSA-SHA256 PKCS#1 v1.5 над рядком `{timestamp}.{сире тіло}`. Публічний ключ:
https://api.ukrainealarm.com/webhook-public.pem (копія в `server/src/ukrainealarm.ts`).
Радять відкидати повідомлення, старші за 5 хв, і дублікати.

Тіло:

```json
{
  "status": "DEACTIVATE",
  "regionId": 14,
  "alarmType": "AIR",
  "createdAt": "2026-09-07T12:18:00Z",
  "alertLevel": "Red",
  "reason": "Missile threat",
  "activeAlertLevels": [
    { "alertLevel": "Yellow", "reason": "UAV activity", "createdAt": "2026-09-07T11:42:00Z" }
  ]
}
```

- `status`, `alertLevel`, `reason` — лише **одна зміна**.
- `activeAlertLevels` — **повний стан** регіону для цього типу після зміни.
  Порожній — тривоги немає. Стан визначаємо тільки за ним.

Не задокументовано: повторна доставка, порядок подій, ID події. Питання до support@stfalcon.com підготовлене (лист від 2026-09-24).

## Ліміти

Офіційно — **ніде не вказані**. Неофіційно (2026-09-24):

- Telegram-бот Yosohanomi: «приблизно 1 запит на хвилину на ключ», перевищення → **401**, а не 429.
- Плагін Noctalia з ключем опитує раз на 10 с.

Тому 401 від ukrainealarm не обов'язково означає поганий ключ. Три запити з інтервалом 60 с
з домашнього комп'ютера пройшли без відмов.

**Заміряно на проді 2026-09-24 (Cloudflare Workers, ще без вебхуків):** щохвилини пара
`/alerts/status` → `/alerts` в одну секунду, 30 хв.

- `/alerts/status` — 30 з 30 успішні.
- `/alerts` — приблизно кожен третій отримує **401** (8 з 22), інколи двічі поспіль.
  Ключ дійсний (сусідні запити проходять), тож 401 тут — ліміт, як і казали інші розробники.
- Схоже на окремий, суворіший ліміт на повний список (порядку 3–4 успішних за 5 хв),
  але чи рахується він разом зі `status`, не з'ясовано.

Висновок для проксі: `/alerts` — дорогий запит, його треба робити якомога рідше;
`/alerts/status` можна щохвилини.

## Умови оферти (коротко)

- Безкоштовно; використання на власний розсуд, зокрема комерційне, крім повного копіювання
  їхнього API заради вигоди (п. 4.4).
- Можуть закрити доступ будь-коли без пояснень (4.2); API «ЯК Є», без відповідальності
  за неотримані чи запізнілі дані (7.3–7.4) — ще одна причина для fail-safe (NFR-1).
- Умови змінюються публікацією нової версії (6.1); про зміни в наданні послуг обіцяють
  попередити листом за 14 днів, «у разі наявності такої можливості» (4.6).
- «Публічний сервіс» визначено як такий, що має унікальну IP-адресу (1.1.8). У воркера
  її немає; це теж є в листі до підтримки.

## Спостереження на проді (2026-09-24/25)

Проксі на Cloudflare Workers, живий ключ, підписка на вебхук з 23:29 UTC.

**Ліміти.**
- `/alerts/status` щохвилини — жодної відмови за години роботи.
- `/alerts` щохвилини — приблизно кожен третій отримує **401**. Після обмеження
  «не частіше ніж раз на 2 хв, після відмови — 3 хв» відмови зникли.
- 401 на підписку вебхука (`POST /api/v3/webhook`) теж був лімітом: той самий ключ саме тоді
  використовував проксі. За хвилину той самий запит пройшов (`200`, порожнє тіло).
  Отже, ліміт, найімовірніше, спільний на ключ, а `/alerts` у ньому «дорогий».

**Вебхуки.**
- Доходять. Затримка від `createdAt` до нас — у середньому ~10 с, максимум ~20 с.
- Відбої в кількох районах приходять пачкою, по кілька за секунди.
- Паузи між подіями бувають по кілька хвилин навіть під час активних тривог, тож перевірка
  на тиші потрібна.
- Бот-захист Cloudflare перед `*.workers.dev` відправника пропускає. Перевірено на типових
  клієнтах (.NET, Go, Java, requests, Node, запит без User-Agent); блокується лише `Python-urllib`
  (помилка 1010).

**`lastActionIndex`.**
- Це .NET `DateTime.Ticks` моменту останньої зміни за UTC: номер, отриманий о 23:21:01,
  розшифровується як 23:20:58.
- Змінюється **частіше, ніж приходять вебхуки**: після деплою порівняння «час номера ≤ найсвіжіший
  вебхук» спрацювало 1 раз, а повний список знадобився 3 рази і ще 2 рази був відкладений.
  Найімовірніше, номер рахує й дії, яких вебхук не надсилає (зміни рівнів загрози, інші типи,
  службові правки). Відкрите питання — варто спитати Stfalcon.
