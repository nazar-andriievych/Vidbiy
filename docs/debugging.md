# Як розслідувати поведінку «Відбою»

Інструменти, якими розбирають «задзвонив не тоді» — і після сценаріїв з `docs/testing.md`,
і після живого прогону.

## Журнал рішень на телефоні

Кожне рішення будильника й разового режиму: час, регіон, покривні UID, вік даних, рівні над
регіоном, рішення (`decideRing`) і крок (`retry` / `wait` / `pause` / `ring`). Лише на телефоні,
нікуди не надсилається, у резервну копію не потрапляє.

- У debug-збірці: «Налаштування» → внизу «Журнал рішень (debug)».
- З ПК: `adb exec-out run-as ua.vidbiy.app cat files/decisions.jsonl`
- Logcat (лише поки свіжий): `adb logcat -s VidbiyWait VidbiyAlarm AlertsClient VidbiyLockedBoot AlarmRingService`

До першого розблокування після перезавантаження журнал не пишеться (сховище недоступне);
ці дзвінки з'являються в ньому після розблокування як `locked_ring`.

## Стан на сервері зараз

```
node tools/check-region.mjs 702          # Буча (громада) → 702, 75, 14
node tools/check-region.mjs Буча
node tools/check-region.mjs 702 --proxy http://127.0.0.1:8787
```

Друкує рівні над регіоном, рішення для «Будь-яка» / «Лише червона» і події сервера по цих
регіонах за 6 год (`/log`: вебхуки й знімки, було → стало). Журнал сервера тримає 48 год.

## Що стоїть в AlarmManager

```
adb shell dumpsys alarm | findstr vidbiy
```

Звичайні спрацювання — дії `FIRE_ALARM` / `FIRE_SNOOZE` / `FIRE_DEADLINE`, вартовий —
`FIRE_WATCHDOG`, до розблокування після перезавантаження — `FIRE_LOCKED`. Порожньо, а будильник
увімкнений — будильник не задзвонить (див. «Дозволи» в `docs/testing.md`).

## Як читати журнал

Знайти рядок `ring` і попередні `poll`.

| Що в журналі | Що це означає |
|---|---|
| `fire` | Спрацював час будильника (або відкладення, крайній час — видно в `note`) |
| `poll` з `step: retry` | Перші 30 с: свіжих даних ще немає, пробуємо знову (FR-8) |
| `poll` з `step: wait` / `pause` | Тривога триває / іде пауза після відбою (FR-14) |
| `decision: RING_CLEAR`, `levels: []` | Проксі сказав «тривоги немає». Звірити з офіційним застосунком і з `/log` сервера: хто зняв тривогу — вебхук чи знімок |
| `RING_CLEAR`, а в `levels` жовта, `waitFor: RED_ONLY` | Так налаштовано: чекали лише червону |
| `RING_STALE` / `RING_NO_DATA` | Fail-safe: немає свіжих даних (мережа, проксі, ukrainealarm) |
| `RING_ALERT_TOO_LONG` | Рівень оголошено понад добу тому (дата в `levels`) або минула доба очікування |
| `ring` з `FIRE_DEADLINE` | Крайній час або доба очікування (страховка в AlarmManager) |
| `ring` з `FIRE_SNOOZE` | Відкладений дзвінок: дзвонить незалежно від тривоги (FR-20) |
| `ring` з `WATCHDOG: APP_FAILURE` | Служба очікування замовкла (її вбила система) — вартовий задзвонив за ≤5 хв |
| `ring` з `LOOP_FAILURE: APP_FAILURE` | Виняток у циклі очікування — дзвонимо замість мовчання (LOGIC-1) |
| `restore_wait` | Очікування відновлено після перезавантаження чи оновлення (`note` — чому) |
| `locked_ring` | Дзвінок до першого розблокування після перезавантаження (`note`: `ALARM` / `SNOOZE` / `WAIT`) |
| `auto_snooze` / `missed` | Дзвінок без відповіді відклав себе сам / здався (FR-21a) |
| `cancel_snooze` | Відкладення скасоване |
| `gapSeconds` значно більше 30 | Телефон (енергозбереження Samsung) розтягує опитування |
| `fetch: timeout` / `no_network` / `http_…` | Ця спроба не вдалась; рішення — на попередніх даних (FR-15), їхній вік у `ageSeconds` |
| `confirmedAt` | Момент, який сервер підтвердив, — за ним рядок звіряється із сервером (UTC) |
| тривога в області, а регіон — область | Області бачать лише тривоги, оголошені на всю область; ukrainealarm здебільшого оголошує по районах |
